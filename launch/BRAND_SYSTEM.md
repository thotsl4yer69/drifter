# MAZLABZ / DRIFTER VIM — Brand System v1

**Public signature:** MAZLABZ / DRIFTER VIM  
**Product expansion:** Vehicle Intelligence Module  
**Internal project name:** DRIFTER  
**Stage:** Hardware-integrated prototype / founding beta

## Brand premise

**The fault vanished. The evidence didn't.**

DRIFTER VIM is positioned as a persistent local vehicle-intelligence node, not another phone code reader. The product story starts with evidence around intermittent faults: live telemetry, incident capture, ordered sensor changes and a dedicated in-car appliance.

## Naming

Use **MAZLABZ / DRIFTER VIM** in primary external identity.

Use **DRIFTER VIM — Vehicle Intelligence Module by MAZLABZ** on first formal mention.

Do not launch the bare word **DRIFTER** as the sole market-facing identity. An unrelated active business currently uses Drifter in mobility intelligence, vehicle data, edge devices and parking, creating avoidable market ambiguity.

### Semantic rule

Cyan, amber and red are state colors, not decorative brand accents.

- cyan = live / connected;
- amber = warning / unresolved attention;
- red = fault / failed state;
- white = primary information;
- graphite = structural surfaces.

## Evidence rule

Never present invented telemetry as field evidence.

Screenshots, graphs, fault timelines, RPM, DTCs, temperatures, GPS positions, compatibility results and acceptance outcomes shown as proof must come from real recorded runs.

Illustrative diagrams are allowed when obviously explanatory rather than presented as measured output.

## Voice

Use:
- specific;
- measured;
- mechanical;
- evidence-led;
- concise;
- explicit about state.

Examples:
- “Adapter connected / ECU waiting.”
- “90 seconds before. 45 seconds after.”
- “Targets standards-based OBD-II vehicles.”

Avoid:
- “works with every car”;
- “dealer-grade AI diagnosis”;
- “predicts every failure”;
- unsupported root-cause claims.
