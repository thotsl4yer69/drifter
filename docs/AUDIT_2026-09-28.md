## Exact software changes

### Boot wait

`src/boot_manager.py`: each service probe receives at most the remaining shared readiness budget; sleep is capped; no new post-deadline probe sweep runs; declared order and previously observed successes are preserved; unobserved services remain degraded. No systemd unit, service list, power or framebuffer configuration changes.

The baseline took **24 simulated seconds for a 1-second budget** with four stalled probes. This is a software reproduction, not a measured Pi boot. Process creation/reaping and OS scheduling can add overhead; network/MQTT waits and whole-system boot are separate concerns. Process-active is not application-ready or ECU-online.

`tests/test_boot_manager.py` updates the shared-window fixture. `tests/test_boot_manager_deadline.py` adds 17 timing, state and timeout cases.

### OBD proof

`src/obd_setup_strict.py`: rejects non-finite/non-positive/boolean timestamps and invalid clocks, preserves signed age, rejects future retained evidence, catches conversion overflow, and requires literal boolean true for adapter/ECU flags. Numeric timestamp strings remain compatible. Invalid evidence stays degraded and cannot open a second ELM connection while the running bridge owns it. Protocol negotiation, pairing and persistence are unchanged.

Baseline reproductions included NaN/future timestamps and the string `"false"` being treated as success. `tests/test_obd_status_freshness.py` adds 46 cases. The touchscreen TEST ECU HTTP route invokes this strict CLI, but the HTTP/UI workflow was not run end-to-end. This fix does not authenticate publishers or equate a heartbeat with fresh vehicle samples.
