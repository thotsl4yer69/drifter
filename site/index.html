Not another phone code reader.

Most OBD tools answer the question you ask now. DRIFTER is built for the harder problem: keeping the context around faults that are intermittent, short-lived or difficult to reproduce.

Always-on evidence

The vehicle node keeps a bounded rolling window and can preserve evidence when a fault or operator capture occurs.

Dedicated touchscreen

Vehicle-link state, live telemetry, diagnostics and capture controls live on the node rather than requiring a phone for the core workflow.

Local-first

Telemetry and service logic run on the Raspberry Pi using a modular Linux/MQTT architecture.

The incident black box.

When a trigger fires, DRIFTER preserves a bounded window around the event and orders material sensor changes so the investigation starts with evidence instead of memory.
